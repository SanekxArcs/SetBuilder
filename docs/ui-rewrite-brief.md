# WPF rewrite of the Set Builder frontend (1.6.0)

Goal: replace the hand-drawn WinForms UI (MainForm.cs, AnalyticsPanel.cs, Fluent.cs, Controls.cs, Shell.cs) with a WPF + WPF-UI 4.3.0 frontend that looks like a native Windows 11 app, exactly the way `C:\Users\Sanekx Arcs\Documents\Repos\personal\cursor-lang\LanguageCursor` does it (FluentWindow with Mica, `ui:TitleBar`, cards with a title and a description, section headers, `ui:ToggleSwitch`, theme brushes only). The core (Automation.cs, Workflow.cs, RunLedger.cs, SessionLog.cs, Desktop.cs, Analytics*.cs, Models.cs, Verification*.cs, ZonePicker.cs, NotificationAudio.cs) stays as it is. Every behaviour, label, explanatory text and setting of the old UI must survive; the exhaustive inventory of the old UI is the source of truth for that (path given in your task).

## Conventions every page follows
- Namespace `TunerFest.Ui.Pages` for views, `TunerFest.Ui.ViewModels` for view models. Files: `Ui/Pages/<Name>Page.xaml(.cs)`, `Ui/ViewModels/<Name>ViewModel.cs`. Extra helpers of a page go to `Ui/<Something>.cs` with a name that cannot collide with other agents (prefix with the page name when in doubt).
- `public partial class <Name>Page : UserControl` with constructor `<Name>Page(<Name>ViewModel vm) { DataContext = vm; InitializeComponent(); }`.
- `public sealed class <Name>ViewModel(IShellContext shell) : PageViewModel(shell)`.
- Settings are **properties on the view model that read and write `Shell.Profile` directly**. Save behaviour must match the inventory: where the old UI saved on change, call `Shell.SaveProfile()` in the setter; where it saved "at start", only write the profile (the shell validates with `ProfileRules.Validate` and saves when a run starts). Never call `Profile.Save()` yourself.
- Everything that must be disabled while a run is in progress binds `IsEnabled="{Binding CanEdit}"` (on the card or the control). Override `Refresh()` to raise PropertyChanged for every property so the shell can refresh the page after `AutoSetApplied` or when `IsBusy` changes (always call `base.Refresh()`).
- Dialogs: use `Shell.Window` as the owner; when it is null (preview) do nothing and `Shell.Log(...)` instead. Use WPF dialogs (`Microsoft.Win32.OpenFileDialog`, `OpenFolderDialog`) and WPF `Clipboard`; never WinForms except the existing `ZonePicker` (a WinForms Form; shown with `ShowDialog()` from the zones page).
- Name clashes: `System.Drawing` is a global using. In WPF code-behind and view models add aliases as needed, e.g. `using Color = System.Windows.Media.Color;`, `using Brush = System.Windows.Media.Brush;`, `using Point = System.Windows.Point;`, `using Size = System.Windows.Size;`, `using Image = System.Windows.Controls.Image;`, `using FontFamily = System.Windows.Media.FontFamily;`. Use `System.Windows.MessageBox` only if the inventory shows a message box.
- Text: copy every Ukrainian label, description and log message **verbatim** from the inventory. Explanatory paragraphs become `CardDescription` text under the card title; section labels in capitals become `SectionHeader` text in normal case (e.g. "НАТИСКАННЯ ТА ШВИДКІСТЬ" → "Натискання та швидкість").
- Look: only theme brushes (`TextFillColorPrimaryBrush`, `TextFillColorSecondaryBrush`, `AccentFillColorDefaultBrush`, `CardBackgroundFillColorDefaultBrush`, …). No hard-coded colours except semantic ones the inventory names (log categories, status dot). Controls: `ui:CardControl` (one setting per card: title + description on the left, control on the right), `ui:CardExpander` for groups, `ui:ToggleSwitch`, `ui:NumberBox` (set `Minimum`, `Maximum`, `SmallChange`, `ClearButtonEnabled="False"`, bind `Value` TwoWay; it is a `double`), `ComboBox` (`ItemsSource` + `SelectedItem`/`SelectedValue`), `ui:Button` with `Icon="{ui:SymbolIcon Name24}"` and `Appearance="Primary"` for the one primary action, `ui:TextBox`, `ui:InfoBar`, `ui:SymbolIcon`. Page root: `<ScrollViewer Style="{StaticResource PageScroll}"><StackPanel Style="{StaticResource PageBody}">…`. First element: `<TextBlock Style="{StaticResource PageTitle}">` with the page name, then one `CardDescription` line.
- Combo boxes with icons (build page) use an `ItemTemplate` with a 20 px `Image` and the title.
- Smoke: override `SmokeChecks(ICollection<string> passed)` and port the checks the inventory lists for your page (section 5), adding `"PASS ..."` lines (keep the same meaning; wording may change). Run them yourself against `new PreviewShell()` in a tiny temporary console or by calling them from the preview tool is not possible, so at least make sure the code paths are exercised in the preview (the shell runs them in `--ui-smoke`). Throw `InvalidOperationException` on failure.
- `PreviewVariants`: if the inventory lists extra screenshots for your page (auto-set view, analytics inner tabs, expanded log), expose them.
- Keep the WPF-UI symbol names valid: check `~/.nuget/packages/wpf-ui/4.3.0/lib/net8.0-windows7.0/Wpf.Ui.xml` (grep for `SymbolRegular.`) or use well-known ones (Settings24, Keyboard24, DocumentBulletList24, Alert24, DataBarVertical24, ScreenSearch24, Play24, Stop24, FolderOpen24, Open24, ArrowSync24, Timer24, Wrench24, Beaker24, Image24, ZoomIn24, Copy24, Delete24, TextFontSize24, DarkTheme24).
- Build with `dotnet build SetBuilder.csproj -c Release -nologo -v q` from the repo root of **your worktree**; it must have 0 errors. Run the full offline suite with `./Test.ps1` only if you touched Program.cs (shell agent).
- Do not touch files owned by other agents. Page agents only add their own files (plus their own helpers). The shell agent owns `Program.cs`, `Shell.cs`, `Ui/App.xaml`, `Ui/MainWindow.xaml`, `Ui/MainViewModel.cs`, `Ui/Shell/*`, and deletes the old UI files. Do not edit `Ui/ShellContext.cs`, `Ui/Themes/Styles.xaml` or `Ui/Converters.cs`; if you need something there, write it in your own file and mention it in your report.
- Finish by committing on your worktree branch with a one-line message (`git add -A && git commit -m "ui: <page> page in WPF"`), and report: the branch name, the files you added, the preview PNG path you checked, and anything the shell must know (names of public members other parts use, smoke PASS lines, open questions).
